# Runde 21 — Landing

**Status:** läuft · **Screen 7 von 10** · Route `/taste/21/`

Die letzte fehlende Vorlage und der erste Screen **außerhalb** der App: Navigation oben,
große Typo, ein Bild, das kein Foto ist. Hier entscheidet sich, ob „Laut" auch im
Marketing trägt.

## H1 — Hero: geteilt, nicht zentriert

**Ableitung.** Alles, was er behalten hat, war **zweispaltig oder geführt**: Login geteilt
(Runde 18), Kurs Chart + Spalte (Runde 17), Artikel Text + Rand (Runde 16). Zentrierte
Hero-Blöcke hat er nie gewählt.
**Prognose.** `02 Geteilt` (Text links, Visual rechts) gewinnt; `01 Zentriert` verliert.
**Gegenprobe.** Wenn `01` gewinnt, ist die Landing ein eigener Seitentyp mit Bühne —
dann gilt die Zwei-Spalten-Regel nicht für Marketing.

## H2 — Größe: ein Satz, kein Absatz

**Ableitung.** Runde 12: ein großer Titel trägt den Screen; der Rest bleibt klein. Runde 16:
Lesetext ist schmal (45 Zeichen).
**Prognose.** Der Hero besteht aus **einem** Satz (max. 8 Wörter) und einem Lead von höchstens
zwei Zeilen. `03 Editorial` mit Riesen-Typo gewinnt die Typo, verliert aber, wenn der Text
zu lang wird.
**Gegenprobe.** Wenn `03` gewinnt, darf Marketing lauter sein als die App.

## H3 — Shell: Navigation oben, drei Punkte

**Ableitung.** Die App hat eine Seitenleiste (Runde 11); für eine öffentliche Seite ist
oben die einzige Stelle, die ohne Umbau funktioniert. Drei Punkte reichen (Runde 17: Tabs
schaffen Ordnung, nicht Menge).
**Prognose.** Eine Zeile mit Marke links, drei Links, einer Aktion rechts. Kein Burger-Menü
auf Desktop.
**Gegenprobe.** Wenn mehr Punkte oder ein Menü gewünscht sind, ist die Shell voller als gedacht.

## Fünf Varianten

| # | Slug | Was anders ist |
|---|---|---|
| 01 | `01-zentriert` | Hero mittig, Visual darunter, drei Spalten Features |
| 02 | `02-geteilt` | Hero links, Visual rechts, Features darunter |
| 03 | `03-editorial` | Riesen-Typo, eine Spalte, Features als Nummernliste |
| 04 | `04-bento` | Hero oben, Features als Bento-Raster mit Flächen |
| 05 | `05-ruhig` | kleiner Hero, dichte Feature-Liste, wenig Bühne |

## Ergebnis

**06 Bento mittig gewinnt** — Bento-Raster mit **mittigem** Hero. Gebaut als sechste Variante.

- **H1 Hero — widerlegt.** Nicht geteilt: die Landing darf eine **Bühne** haben, der Hero
  steht mittig wie in 01. Zwei Spalten gelten für App-Seiten, nicht für Marketing.
- **H2 Größe — bestätigt.** Ein Satz, kurzer Lead; der Titel bleibt bei 52 px.
- **H3 Shell — bestätigt.** Marke links, drei Punkte, eine Aktion rechts.
- **Bento — neu.** Die Eigenschaften sind Flächen im Raster, nicht drei Textspalten.
  Das ist der erste Screen mit einem echten Raster.

## Erkenntnisse

1. **Landing = mittiger Hero + Bento-Raster.** Die Ausnahme von der Zwei-Spalten-Regel.
2. Die Bühne ist Typo plus Fläche, kein Foto. Das Visual ist eine Kornfläche mit einer Zahl.
3. Die Shell bleibt eine Zeile: Marke, drei Punkte, Aktion.
